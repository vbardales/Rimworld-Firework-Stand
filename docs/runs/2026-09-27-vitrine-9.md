# Pickle run: the Workshop gallery, feature 14, pass vitrine, 2026-09-27 (ninth request, 2911) — the root cause

- **exitReason:** `failed`, `setName` `vitrine` (request 2911): 4 scenarios played, 3 passed, 1 failed. Run on the tree of
  `f5a51de` (the timeouts raised; the step now returned its own message again instead of timing out).
- **The failure, fifth time, and this time the trace names the cause:** `gallery 04`, "after 30 s the stand's light never
  came on". `tick 102976 shot@102975 departed=False lit=False shouldBeLitNow=False spawned=True glows=False` then
  `tick 103036 ... departed=True lit=True shouldBeLitNow=False spawned=True glows=False` then `tick 103276 ... lit=False
  shouldBeLitNow=False`. **Our comp says yes (`lit=True`), the stand is spawned, and the game's own `ShouldBeLitNow` says
  no.** So another comp of the building voted no.
- **The cause (found by reading the game, which I had done incompletely on 2026-09-26):** `CompRefuelable` implements
  `IThingGlower` (the game has 23 implementers, `CompRefuelable` among them) and answers "no light" when it holds no
  fuel. `CompGlower.ShouldBeLitNow` asks every such comp and gives up on the first no. The stand spent its launcher as the
  rocket left, so with one launcher loaded (this scenario) it held none during the light, and the light was refused. The
  stands of the other scenarios held two or more launchers, so the light was seen there: which is why 05-light was green
  while the gallery was red. On 2026-09-26 I had read only `CompGlower`'s own IL and concluded (wrongly) that fuel played
  no part; the hypothesis I refuted was the right one, tested at the wrong place.
- **A real defect of the mod, not of the test:** with the stand's last launcher, the ground was never lit. Fixed in
  `Source/CompFireworkStand.cs`: the launcher is spent when the light goes out (`consumePending`, saved), a shot that
  does not leave still spends it at once. CHANGELOG and the Steam change note say so. A functional test now reads the game
  (`CompRefuelable` is an `IThingGlower`) and the mod (the field, the spending from `CompTick`). 33 tests, all passing.
- **What this run also shows:** the earlier timeouts (four runs) hid this: the step now returned its message because the
  budget was raised. The raise stays: the scene does tick slower than real time.
